### ۱-۲. مقایسهٔ دو نسخه پیش از بازگردانی (کامیت `19f41a6`)

- موتور خالص `src/lib/report/version-diff.ts` (بدون I/O، بدون وابستگی جدید).
- مسیر `GET /api/projects/:id/versions/:version/diff?against=<n|current>` با سهمیهٔ ۱۲۰/دقیقه.
- قرارداد پاسخ: `{ id, from, to, diff: { identical, counts:{added,removed,changed,total}, settings[], groups[] } }`؛ هر ورودی `fields[{key,label,before,after}]` دارد.
- قاعده‌های معنا (همه آزمون‌شده): تنظیمات گزارش (`meta` + `calendar` + `pricing`) **یک** تغییر شمرده می‌شوند، نه ده‌ها؛ ترتیب کلیدهای JSON بی‌اثر است؛ `""` با «نبودن» یکی است؛ کلید ناشناخته هم با برچسب خام نشان داده می‌شود (پنهان نمی‌شود).
- رابط کاربری: در `ReportView.tsx` کنار هر نسخه «مقایسه با نسخهٔ فعلی / قبلی»، پنل قبل/بعد با شمارش افزوده/حذف/تغییر، و سپس دکمهٔ بازگردانی — مقایسه **پیش از** بازگردانی، نه بعد از آن.

### ۱-۳. اعتبارسنجی سخت‌گیرانهٔ پارامترها (کامیت `ccd9c13`)

این بخش از یک آزمون خصمانهٔ واقعی روی build تولیدی بیرون آمد، نه از حدس:

| ورودی | رفتار قبلی (یافته) | رفتار فعلی |
| --- | --- | --- |
| `/versions/1.5` | `200` — با `parseInt` به نسخهٔ ۱ تبدیل می‌شد | `400` |
| `/versions/1e3` | `200` — همان تور‌شدن | `400` |
| `/versions/999999999999999999999` | **`500`** — سرریز `int4` در PostgreSQL | `400` |
| `?limit=99999` / `-5` / `abc` | بی‌صدا نادیده گرفته می‌شد (`200`) و هر ۱۰۰ نسخه برمی‌گشت | `400` + سقف ۱۰۰، پیش‌فرض `HISTORY_LIMIT` |
| `against=0` / `against=abc` | — | `400` |
| uuid نامعتبر | `400` | `400` (بدون تغییر) |

سازوکار: `parsePositiveInt(raw, max)` در `src/lib/server/http.ts` — الگوی `^[1-9]\d{0,8}$`، `Number.isSafeInteger` و سقف صریح؛ خطای عددی **رد** می‌شود، نه بریده.

### ۱-۴. فهرست پروژه‌ها: صفحه‌بندی، سهمیه، خطای صادقانه (کامیت `061e18e`)

| یافته | اقدام |
| --- | --- |
| `GET /api/projects` همهٔ پروژه‌های کاربر را بدون سقف برمی‌گرداند؛ با گذشت زمان کند و حجیم می‌شد | `limit`/`offset` با سقف ۵۰، پیش‌فرض ۲۰؛ پاسخ `{projects, total, hasMore, nextOffset}` |
| فهرست هیچ سهمیه‌ای نداشت (دو کوئری در هر فراخوانی) | سهمیهٔ ۱۲۰/دقیقه روی همان ذخیره‌گاه مشترک PostgreSQL + `Retry-After` |
| خطای پایگاه داده به «فهرست خالی» تبدیل می‌شد — کاربر فکر می‌کرد کارش از دست رفته | حالا `500` با پیام روشن |
| رابط کاربری فقط می‌گفت «پروژه ذخیره‌شده‌ای یافت نشد» حتی وقتی خطا رخ داده بود | پیام خطای واقعی + دکمهٔ «نمایش پروژه‌های بیشتر» با تعداد کل |

### ۱-۵. خروجی صفحه‌گسترده: تزریق فرمول (CWE-1236) (کامیت `061e18e`)

- `csvSafe()` قبلاً `=`, `+`, `@`, tab و CR را خنثی می‌کرد ولی `-` را نه.
- حالا سلولی که با `-` شروع می‌شود و **عدد نیست** با آپاستروف خنثی می‌شود؛ اعداد منفی لاتین و فارسی (`-5`، `-۱۲۳`، `-5,200`) دست‌نخورده می‌مانند.
- آزمون، رفتار واقعی را می‌سنجد (عنوان مخرب `=HYPERLINK("http://evil.example","click")` و نام پروژهٔ `-2+3+cmd|' /C calc'!A0`)، نه وجود رشته در سورس.

## ۵. واقعی در برابر پیشنهادی

### ۵-۱. واقعی (اجرا شد و شاهد دارد)

1. تاریخچهٔ نسخهٔ تغییرناپذیر + هرس + بازگردانی حسابرسی‌شده.
2. ویرایش هم‌زمان با `409` و ویرایش دوباره با نسخهٔ درست.
3. بازسازی نسخهٔ گمشده برای پروژه‌های بی‌تاریخچه.
4. مقایسهٔ دو نسخه (موتور خالص + API + رابط) با معناهای مستند.
5. اعتبارسنجی سخت‌گیرانهٔ همهٔ پارامترهای تاریخچه و فهرست.
6. صفحه‌بندی + سهمیه + خطای صادقانهٔ فهرست پروژه‌ها، و «نمایش بیشتر» در رابط.

## ۷. ریسک‌های باز (که با این کار بسته نشد)

1. **هرس تاریخچه** یعنی بازگردانی به نسخه‌ای که هرس شده ممکن نیست؛ این سیاست مستند شده ولی سقف آن باید با نیاز شما تنظیم شود.
2. **فهرست پروژه‌ها** برای کاربر با هزاران پروژه: `count(*)` در هر درخواست؛ در مقیاس بزرگ کشیدن شمارش به ایندکس/تقریب لازم می‌شود.
3. **مقایسهٔ نسخه‌های بزرگ** یک پاسخ کامل در حافظه می‌سازد؛ برای پروژه‌های چند‌هزار فعالیتی صفحه‌بندی گروه‌ها لازم است.
4. **رابط مقایسه** فقط با SSR/چیدمان ایستا و `a11y` خودکار بررسی شده؛ کلیک واقعی در مرورگر آزمون نشده.
5. **Pool پایگاه در serverless** و رفتار cold start آزمون نشده.
6. **CSV** رفتار Excel/Google Sheets روی همهٔ نسخه‌ها آزمون نشده؛ خنثی‌سازی استاندارد است ولی تضمین مطلق نیست.

## ۹. پیوست — تشخیص و رفع «خروجی ۴۰۴ می‌دهد»

**گزارش شما:** «قبلاً سایت خروجی واقعی می‌داد، الان ۴۰۴ می‌دهد.»

**تشخیص (با آزمون روی build تولیدی، نه حدس):**

| سناریو | کد وضعیت | جمع‌بندی |
| --- | --- | --- |
| `/report/<id>` با همان مرورگر/کوکی سازنده | **۲۰۰** (HTML کامل ~۲۰۲KB، نمودار، جدول‌ها) | گزارش سالم است |
| `/report/<id>` از مرورگر یا دستگاه دیگر | **۴۰۴** (عامدانه، فقط مالک) | علت اصلی ۴۰۴ همین است |
| `/s/<token>` از مرورگر دیگر (لینک اشتراک) | **۲۰۰** | مسیر درست اشتراک‌گذاری کار می‌کند |
| `POST /api/export` (XLSX/CSV/…) | **۲۰۰** با فایل واقعی | خروجی فایل سالم است |
| `/api/projects?limit=0` | ۴۰۰ | اعتبارسنجی درست |

یعنی ۴۰۴ «خرابی خروجی» نبود؛ **سیاست دسترسی مالک‌محور** بود که با پیام گمراه‌کننده
«ممکن است حذف شده باشد» همراه شده بود. مهم‌ترین حالت واقعی: پروژهٔ مهمان با کوکی همان مرورگر
شناسایی می‌شود؛ مرورگر دیگر، کوکی پاک‌شده یا دامنهٔ پیش‌نمایش تازه = مالک شناخته نمی‌شود.

**اقدام‌ها (این دور):**

1. صفحهٔ ۴۰۴ گویا برای `/report/[id]` و `/s/[token]`: همان کد ۴۰۴ و همان متن برای هر سه حالت
   (حذف‌شده/نشانی اشتباه/غیرمالک) تا وجود پروژه افشا نشود، اما مسیر بازیابی هم گفته می‌شود
   (همان مرورگر، ورود با موبایل، درخواست لینک اشتراک تازه). آزمون: `production-smoke.txt`.
2. **فایل پشتیبان پروژه** (`src/lib/project-file.ts` + «پروژه‌های من ← فایل پشتیبان/بازیابی از فایل»)
   برای انتقال کار بین مرورگرها بدون وابستگی به کوکی؛ اعتبارسنجی دوباره هنگام ورود.
   آزمون: `npm run test:project-file` — **۳۱ بررسی**.
3. `POST /api/projects/:id/share` با بدنهٔ خالی اکنون ۲۰۱ می‌دهد (قبلاً ۴۰۰ می‌داد) و بدنهٔ ناقص
