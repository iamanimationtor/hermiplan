# account slot. `display:none` does not unmount a dialog: on a phone it existed in
# the DOM and painted at 0×0, so the «ورود / ثبت‌نام» link from the landing page
# opened nothing the visitor could see or touch. The panel is now rendered once
# at page level and driven by both triggers (header, action-bar 👤); the suite
# checks, per width, that exactly one dialog exists, that its panel and close
# button really paint inside the viewport, that Escape closes it, and that it
# reopens from this width's trigger.
#   ✗ (before the fix) دیالوگ ورود واقعاً رندر می‌شود — {"x":0,"y":0,"width":0,"height":0}
#   ✗ (before the fix) دکمهٔ بستن دیالوگ ورود قابل لمس است — {"x":0,"y":0,...}
#   → 8 failures of 176, exit 1.  After the fix: 196 of 196 pass (exit 0).
#
# ── report page coverage ─────────────────────────────────────────────────────
# The report header now keeps two actions plus «⋯» on a phone and reveals the
# rest (Excel, link copy, share, history) in a sheet, so no action is
# unreachable at 320 px. The suite checks header width, off-screen controls and
# the sheet itself; without a database the section reports itself as skipped.

# ── regression proof ─────────────────────────────────────────────────────────
# Temporarily restoring the old hard-coded `inline-flex` in the shared Button
# (the root cause) and rebuilding makes this same suite fail 18 of 152 checks
# and exit 1, for example at 320 px:
#   ✗ مرحله 1: عرض سند برابر نمایشگر است — doc=320 body=399 vw=320
#   ✗ مرحله 1: نوار اقدام موبایل کامل داخل نمایشگر است — [{"left":-79,"right":320,...}]
#   ✗ مرحله 1: هیچ کنترلی بیرون از نمایشگر نیست — [{"label":"مرحله بعد",...}]
# With the fix in place all 152 checks pass (exit 0).
