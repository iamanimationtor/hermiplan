## 5) cookie attributes: cross-site frame (https) vs plain http
$ POST /api/auth (register) with `x-forwarded-proto: https`
set-cookie: hermiplan_session=<64 hex>; Path=/; Expires=…; Secure; HttpOnly; SameSite=none
$ POST /api/auth (register) without that header (plain http, local)
set-cookie: hermiplan_session=<64 hex>; Path=/; Expires=…; HttpOnly; SameSite=lax

Reason: `SameSite=Lax` is not sent by the browser inside a cross-site frame, which
turned every opened report into a 404 for its own owner. Over https we now use
`SameSite=None; Secure` (the only combination browsers accept there); over http we
keep `Lax`, because `None` without `Secure` is rejected outright.
