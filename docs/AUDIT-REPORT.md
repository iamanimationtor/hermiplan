# گزارش ممیزی، اصلاح و ارتقای HERMIPLAN

مبنا: مأموریت «ممیزی جامع، اصلاح و ارتقای فنی HERMIPLAN» — مخزن `iamanimationtor/hermiplan`، شاخه
`arena/2f8571d5-hermiplan`.

> **وضعیت فاز:** گزارش پیشرفت ارائه‌شده؛ تأیید نهایی در انتظار بررسی شواهد.
> جدول تطبیق کامل معیارهای مأموریت در [`docs/PROMPT-COMPLIANCE.md`](PROMPT-COMPLIANCE.md) و
> خروجی خام آزمون‌ها در [`docs/evidence/`](evidence/) قرار دارد.

این گزارش **فقط کارهای انجام‌شده و آزمون‌های واقعاً اجراشده** را ثبت می‌کند. هر جا کاری انجام
نشده یا آزمونی اجرا نشده، در همان بخش با صراحت نوشته شده است. هیچ آزمونی «فرضی موفق» ثبت نشده.

## ۲. تغییرات معماری

1. **لایه‌بندی صریح**: `lib/engine` (محاسبه خالص، بدون React و بدون I/O) ← `lib/market`
   (نرخ/هزینه) ← `lib/report` (تولید خروجی) ← `app/api` (فقط اعتبارسنجی، احراز هویت، محدودیت
   نرخ، قالب پاسخ). هیچ محاسبه‌ای در کامپوننت انجام نمی‌شود.
2. **یک مسیر واحد برای ورودی عددی**: `normalize-input.ts` + اسکیمای Zod ⇒ گرد کردن و کلمپ
   فقط یک‌بار، بنابراین «نمایش» و «محاسبه» همیشه هم‌خوان‌اند.
3. **یک مسیر واحد برای تاریخ→موقعیت**: `resolveDatePosition` در `calendar.ts` برای تاریخ
   وضعیت/مهلت/محدودیت‌ها، با تشخیص‌های صریح.
4. **تشخیص‌های ساختاریافته**: `Diagnostic { kind, severity, code, activityIds, message }` جای
   رشته‌های پراکنده؛ `kind` مقوله را مشخص می‌کند (داده، چرخه، منطق شبکه، محدودیت، تقویم، ظرفیت)
   و `status` تحلیل از همین‌ها مشتق می‌شود (`valid/warning/inconsistent/invalid/internal-error`).
5. **یک تصویر از نرخ‌ها**: `MarketSnapshot` از گرفتن تا اعمال؛ آنچه کاربر می‌بیند همان چیزی است
   که اعمال می‌شود؛ ردیف‌های نامعتبر قرنطینه و `feedError` گزارش می‌شود.
6. **حریم خصوصی به‌صورت پیش‌فرض**: پروژه/profile موجودیت مالک دارد، گزارش خصوصی است و مسیر
   مشاهده اشتراکی فقط با توکن ۲۵۶ بیتی (فقط هش در پایگاه داده) باز می‌شود؛ UUID مجوز نیست و
   ساخت/ابطال/مصرف لینک در `project_events` ثبت می‌شود.
7. **لایه سرویس سرور** (`lib/server`): `auth`, `otp`, `sms`, `rate-limit`, `http` — قابل آزمون
   جدا از مسیرهای Next.

## ۷. پیشنهاد فاز بعد (به ترتیب اولویت)

   `npm run db:migrate && npm run test:api` تا تفاوت‌های PGlite پوشش داده شود.

   روشن شد؛ طراحی پیشنهادی: نقش‌ها در سطح پروژه با جدول واسط و مجوزهای ریزدانه.
6. **پیوند به فهرست‌بها**: ورود داده رسمی فقط با سند و امضای دیجیتال؛ تا آن زمان ارجاع
   «مرجع/برآوردی» حفظ شود.
7. **EVM پیشرفته**: EAC وزنی (BAC/CPI و فرمول‌های ETC مستقل) به‌عنوان گزینه قابل انتخاب با
   مستندسازی، و ثبت تاریخ‌دار هزینه‌های واقعی برای `costDataCoverage=100٪`.
