## ۵. امنیت و داده — توضیح جداگانه

**الف) مجوز API.** همه مسیرهای پروژه سمت سرور بررسی می‌کنند: `GET/PATCH/DELETE /api/projects/:id`،
`/share`، `/versions` و `/versions/:n/restore` فقط برای مالک (کوکی مهمان یا نشست) باز است و
غریبه همیشه **۴۰۴** می‌گیرد تا وجود پروژه افشا نشود. دانستن UUID مجوز نیست؛ لینک اشتراک جداگانه،
توکنی و قابل ابطال است و به تاریخچه یا داده خام دسترسی نمی‌دهد (آزمون شده در §۳-ج و §۴-ب).

**ب) حفظ داده موجود.** هیچ جدول/ستون/ردیفی حذف یا بازنویسی نمی‌شود. `0004` فقط اضافه می‌کند و
پروژه‌های قدیمی را back-fill نمی‌کند. مسیرهای «انتشار پیش‌فرض» فقط پرچم امنیتی `is_public` را
اصلاح می‌کنند و داده پروژه را تغییر نمی‌دهند.

**ج) مهاجرت.** هر فایل مهاجرت، فایل rollback جفت دارد؛ اجرا در تراکنش؛ checksum برای کشف تغییر
فایل اعمال‌شده؛ فایل بازگشت پایه فقط با جدول تأیید اجرا می‌شود. تمرین کامل «بازگشت → migrate دوباره»
ساختار یکسان تولید می‌کند (`migration-safety.txt`، ۳۳ بررسی) و روی پایگاه نسخه قبل هم آزموده شد
(`legacy-db.txt`: ۲ + ۳۱ + ۹ بررسی).

**د) آنچه هنوز روی PostgreSQL واقعی آزموده نشده است.** محیط چندنمونه‌ای پشت pooler میزبان،
اتصال TLS واقعی ارائه‌دهنده، و رفتار با حجم داده تولیدی. آزمون‌های فعلی روی یک سرور PostgreSQL
۱۸٫۶ واقعی و یک پایگاه دورانداختنی اجرا شده‌اند، نه روی داده یا حساب شما.
