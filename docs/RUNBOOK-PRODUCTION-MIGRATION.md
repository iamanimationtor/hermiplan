# دفترچه اجرای مهاجرت در محیط واقعی (Production Runbook)

> **وضعیت:** مجوز اجرا داده شده («تایید می‌شود»)، ولی **دسترسی به پایگاه و حساب میزبان در این
> محیط وجود ندارد**؛ بنابراین همه‌ی مراحل زیر توسط شما (یا کسی که دسترسی دارد) اجرا می‌شود.
> هر گام، یک خروجی «قابل بررسی» دارد؛ اگر خروجی با ستون انتظار هم‌خوان نبود، **متوقف شوید** و
> گام بازگشت را اجرا کنید.

---

## ۰. پیش‌نیازها

| مورد | چرا لازم است |
| --- | --- |
| `pg_dump` / `psql` (کلاینت PostgreSQL نسخه ≥ ۱۴) | پشتیبان‌گیری و بازگردانی؛ در محیط توسعه ما نصب نبود (بدون root) و همین یکی از «آزموده‌نشده‌ها» است |
| `DATABASE_URL` با دسترسی DDL | اجرای مهاجرت |
| دسترسی به Netlify (Deploy keys / UI) | استقرار کد و rollback |
| تأیید کتبی شما | طبق مأموریت، هیچ تغییری در production بدون آن اجرا نمی‌شود |
| پنجره‌ی کم‌بار (مثلاً شبانه) | `ALTER TABLE` روی `projects` قفل کوتاه می‌گیرد |

متغیرهای محیطی لازم در Netlify (scope = **Functions**):

```
DATABASE_URL=postgresql://…            # الزامی در production
NEXT_PUBLIC_SITE_URL=https://hermiplan.netlify.app   # تا لینک اشتراک آدرس داخلی نسازد
SMS_PROVIDER_KEY=…                     # اختیاری؛ بدون آن ورود موبایل ۵۰۳ می‌دهد
SMS_PROVIDER=…  SMS_OTP_TEMPLATE=…     # در صورت استفاده از سرویس پیامک
```

بازبینی کامل متغیرها: `.env.example` و `DEPLOYMENT.md` §۳.

---

## ۱. پیش‌بررسی (بدون تغییر، روی پایگاه واقعی)

```bash
export DATABASE_URL='postgresql://…'      # آدرس production
npm run db:preflight
```

| نتیجه | انتظار | اگر نبود |
| --- | --- | --- |
| «مهاجرت‌های در انتظار» | `0003_share_tokens` (چون اجرا نشده) | اگر خالی بود، یعنی قبلاً اجرا شده؛ گام ۴ را مستقیم برو |
| «drift» | نباید ظاهر شود | ⛔ متوقف شوید؛ فایل مهاجرت دست‌کاری شده |
| «پایگاه از این نسخه کد جلوتر» | نباید ظاهر شود | ⛔ کد قدیمی روی پایگاه جدید؛ نسخه درست را deploy کنید |
| «ردیف یتیم مالکیت» | صفر | ⛔ `VALIDATE CONSTRAINT` شکست می‌خورد؛ اول تصمیم داده بگیرید |
| «لینک‌های قدیمی غیرفعال» | ممکن است چند پروژه باشد | ⚠️ خطا نیست، ولی قبل از انتشار به مالکان اطلاع دهید (گام ۶) |

> `db:preflight` فقط `SELECT` اجرا می‌کند؛ اجرای آن در ساعات کاری هم بی‌خطر است
> (`--json` برای ثبت در تیکت/لاگ).

## ۲. پشتیبان‌گیری (قابل بازگشت‌پذیر)

```bash
pg_dump --format=custom --no-owner --no-privileges \
        --file="hermiplan-$(date -u +%Y%m%dT%H%M%SZ).dump" "$DATABASE_URL"
ls -lh hermiplan-*.dump          # حجم غیرصفر
pg_restore --list hermiplan-*.dump | head -20   # فایل سالم و خوانا
```

**بازگردانی (آزموده نشده در این محیط — بدون `pg_restore`):**

```bash
pg_restore --clean --if-exists --no-owner --dbname="$DATABASE_URL" hermiplan-….dump
```

پیشنهاد: یک‌بار روی یک پایگاه **آزمایشی** بازگردانی را تمرین کنید و تعداد ردیف‌ها را با
`npm run db:preflight` مقایسه کنید. این تنها گام این دفترچه است که ما نتوانستیم اجرا کنیم.

## ۳. اجرای مهاجرت

```bash
npm run db:status        # فهرست: چه چیزی اعمال شده، چه چیزی مانده
npm run db:migrate       # هر فایل در یک تراکنش جدا
```

| خروجی | معنا |
| --- | --- |
| `✓ 0003_share_tokens (applied)` | مهاجرت اعمال شد |
| `Nothing to do — schema is up to date.` | قبلاً اعمال شده؛ بی‌خطر |
| `✗ … checksum drift` | ⛔ همان لحظه متوقف شوید (فایل مهاجرت تغییر کرده) |

مهاجرت `0003` **فقط‌افزودنی** است: جدول `project_share_tokens` (توکن هش‌شده) ساخته می‌شود و
هیچ ردیف موجودی تغییر نمی‌کند. `0002` ستون‌ها/قیدها/ایندکس‌ها را اضافه می‌کند و پیش‌فرض
`is_public` را به `false` برمی‌گرداند (تصحیح امنیتی).

## ۴. استقرار کد

```bash
git push origin main            # یا از طریق PR؛ Netlify خودش build می‌کند
```

ترتیب مهم است: **اول مهاجرت، بعد کد** (کد جدید جدول `project_share_tokens` را لازم دارد).
اگر برعکس شد، فقط مسیر لینک اشتراک موقتاً ۵۰۰ می‌دهد و بقیه‌ی سایت کار می‌کند.

پس از deploy:

```bash
curl -s https://hermiplan.netlify.app/api/health
# انتظار: {"ok":true,"schemaVersion":4,"database":"ok","rateLimitStore":"postgres",
#          "shareLinks":"postgres","smsConfigured":false}
# اگر ۵۰۳ با "missingTables" دیدید: مهاجرت اعمال نشده — به گام ۳ برگردید.
```

## ۵. تأیید پس از استقرار

| بررسی | فرمان | انتظار |
| --- | --- | --- |
| سلامت + نسخه schema | `curl -s …/api/health` | `ok:true`، `schemaVersion:4` |
| صفحه اصلی و بیلدر | `curl -o /dev/null -w '%{http_code}' …/` و `…/builder` | `200` |
| گزارش با UUID (بدون کوکی) | `curl -o /dev/null -w '%{http_code}' …/report/<uuid>` | `404` (UUID مجوز نیست) |
| لینک اشتراک نامعتبر | `curl … /s/<۴۳ کاراکتر>` | `404` + هدرهای `no-store`/`noindex` |
| CSP | `BASE_URL=https://hermiplan.netlify.app npm run test:csp` | همه‌ی بررسی‌ها سبز |
| یکپارچگی پایگاه | `npm run db:preflight` | بدون مانع |
| چرخه واقعی | ساخت پروژه → گزارش → ساخت لینک → باز کردن لینک در مرورگر ناشناس → ابطال | لینک قبل از ابطال باز، بعد از ابطال ۴۰۴ |

## ۶. لینک‌های قدیمی (پروژه‌هایی که پیش از ۰۰۰۳ «عمومی» بودند)

```bash
npm run db:share-audit          # فقط خواندن؛ --json برای ماشین
```

* پروژه‌های علامت‌خورده، لینک UUID قدیمی‌شان **کار نمی‌کند** (این رفتار درست است: UUID مجوز نبوده).
* **هیچ توکنی به‌صورت خودکار ساخته نمی‌شود**؛ ساختن خودکار یعنی یا توکن را آشکار ذخیره کنیم یا
  لینکی بسازیم که مالک هرگز صادر نکرده — هر دو بدتر از مشکل اصلی است.
* مالک، هنگام باز کردن گزارش، در پنل اشتراک پیام «لینک قدیمی غیرفعال است» و دکمه «ساخت لینک
  جدید» را می‌بیند (پیاده‌سازی‌شده و آزموده).
* پیشنهاد ارتباطی: یک ایمیل/پیام کوتاه به مالکان با متن آماده:

  > «برای امنیت بیشتر، لینک‌های اشتراک گزارش حالا رمزدار و قابل ابطال هستند. لینک قبلی شما
  > غیرفعال شده است. وارد گزارش خود شوید و از دکمه «لینک اشتراک» یک لینک تازه بگیرید.»

## ۷. بازگشت (Rollback)

| لایه | فرمان/اقدام | اثر |
| --- | --- | --- |
| کد | Netlify → Deploys → آخرین deploy سالم → Publish | بازگشت فوری؛ کد قدیمی جدول جدید را نادیده می‌گیرد (**بی‌خطر**) |
| پایگاه (`0003`) | `psql -f drizzle/0003_share_tokens.rollback.sql` و سپس حذف ردیف `0003_share_tokens` از `_hermiplan_migrations` | جدول لینک‌ها حذف؛ **همه لینک‌ها باطل**؛ پروژه‌ها و داده‌شان دست‌نخورده |
| پایگاه (`0002`) | `0002_security_hardening.rollback.sql` + حذف ردیف آن | `attempts` ⇒ text، `rate_limits` حذف، پیش‌فرض `is_public` ⇒ true |
| فاجعه | `pg_restore` از فایل گام ۲ | بازگشت کامل به لحظه پشتیبان |

**ترتیب:** جدیدترین اول (`0003` سپس `0002`). هر دو در `docs/evidence/legacy-db.txt` واقعاً
آزموده شده‌اند (rollback ۶ بررسی، و اعمال مجدد موفق). حذف جدول لینک‌ها داده‌ی کسب‌وکار را
از بین نمی‌برد — تنها بازدیدهای ثبت‌شده لینک از دست می‌رود.

---

## ۸. پس از پنجره

1. `docs/evidence/` را با خروجی واقعی همین اجرا به‌روز کنید (`preflight`, `health`, `test:csp`).
2. `npm run db:preflight` باید «هیچ مانع» بدهد و `db:status` چیزی برای اعمال نداشته باشد.
3. در تیکت انتشار ثبت کنید: نسخه schema، زمان اجرا، اندازه پشتیبان، و فهرست پروژه‌های «لینک قدیمی».

**هشدار:** اگر در گام ۱ یا ۳ هر خروجی غیرمنتظره دیدید، ادامه ندهید. بازگشت ارزان است؛
بازسازی داده نیست.
