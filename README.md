# HERMIPLAN — Project Intelligence Platform

پلتفرم حرفه‌ای مدیریت، برنامه‌ریزی و تحلیل پروژه برای مهندسان، مدیران پروژه، پیمانکاران، مشاوران و دانشجویان.

**Created by Mohammad Shirmardi (محمد شیرمردی)**

---

## اصل محصول

**Simple Input → Smart Processing → Professional Output**

کاربر بدون نیاز به آموزش تخصصی اطلاعات پروژه را وارد می‌کند؛ موتور محاسباتی تمام پیچیدگی‌ها
(مسیر بحرانی، شناوری، زمان‌بندی، تخصیص منابع، هزینه، افزایش هزینه و ریسک) را مدیریت می‌کند و یک
گزارش مهندسی قابل دفاع تحویل می‌دهد.

## قابلیت‌های کلیدی

| حوزه | قابلیت |

## معماری

```
src/
├─ lib/
│  ├─ engine/          # موتور محاسباتی خالص و deterministic (بدون وابستگی به UI)
│  │  ├─ calendar.ts   # تقویم کاری، روزهای کاری، تعطیلات، resolveDatePosition
│  │  ├─ schedule.ts   # مرتب‌سازی توپولوژیک، CPM دو گذره، محدودیت‌ها، تخصیص منابع
│  │  ├─ normalize-input.ts # سیاست واحد گرد کردن مدت/Lag
│  │  ├─ analysis.ts   # تجمیع کامل: WBS، مسیر بحرانی، EVM، ریسک، سلامت، KPI
│  │  └─ types.ts      # مدل دامنه
│  ├─ market/          # کاتالوگ نرخ مرجع + موتور قیمت‌گذاری و سناریوی افزایش هزینه
│  ├─ standards.ts     # استانداردها و متدهای محاسباتی
│  ├─ report/          # موتور خروجی: gantt-svg، xlsx، zip، msproject، html، package
│  └─ templates.ts     # قالب‌های آماده پروژه
├─ components/         # UI (builder، report، charts، nav، logo)
├─ server/             # لایه سرویس: auth، OTP، پیامک، محدودیت نرخ، HTTP
├─ app/
│  ├─ page.tsx         # صفحه اصلی (RTL، ریسپانسیو، موبایل‌فرست)
│  ├─ builder/         # ویزارد ساخت پروژه
│  ├─ report/[id]/     # گزارش A4 + مرکز دریافت خروجی (خصوصی به‌صورت پیش‌فرض)
│  └─ api/             # auth، projects، analyze، market، export، health
└─ db/                 # Drizzle ORM + PostgreSQL
drizzle/               # مهاجرت‌های شماره‌دار + rollback
docs/                  # ENGINE.md (تعریف‌ها) و گزارش ممیزی
```

لایه‌بندی: منطق محاسباتی در `lib/engine` (بدون React)، دسترسی داده در `db/` و `lib/server`،
و مسیرهای HTTP نازک در `app/api` که فقط اعتبارسنجی، احراز هویت، محدودیت نرخ و قالب پاسخ را
انجام می‌دهند.

## اجرا

```bash
npm ci                          # نصب دقیق بر اساس package-lock.json
cp .env.example .env            # DATABASE_URL را تنظیم کنید
npm run db:migrate              # اعمال مهاجرت‌های شماره‌دار
npm run dev                     # یا: npm run build && npm start
```

`npm run db:status` مهاجرت‌های اعمال‌شده/باقی‌مانده را نشان می‌دهد و `npm run db:migrate -- --dry-run`
بدون تغییر پایگاه داده برنامه را چاپ می‌کند.

### PostgreSQL واقعی (بدون Docker و بدون root)

برای آزمون یکپارچگی، `puppeteer`-style وابستگی خارجی لازم نیست: باینری واقعی PostgreSQL از
devDependency `embedded-postgres` اجرا می‌شود.

```bash
npx tsx scripts/pg-dev-server.ts &            # PostgreSQL واقعی روی ۱۲۷٫۰٫۰٫۱:۵۵۴۴
export DATABASE_URL=postgresql://postgres:postgres@127.0.0.1:5544/postgres
npm run db:migrate
npm run build && npx next start -p 3400 &      # NODE_ENV=production
BASE_URL=http://127.0.0.1:3400 npm run test:api        # ۲۳۷ بررسی (locked)
npm run test:db:integrity                              # هم‌زمانی و قیدها
npm run test:csp                                       # سیاست امنیتی محتوا
```

## حالت دسترسی (open / locked)

پیش‌فرض فعلی **`locked`** است: همان سهمیه‌های مستندشدهٔ جدول پایین اعمال می‌شوند. برای دورهٔ
پیش از انتشار می‌توان با یک فرمان همهٔ سهمیه‌های **محصول** را برداشت (`open`: ساخت پروژه، تحلیل،
خروجی و لینک اشتراک بی‌سهمیه). کل این تصمیم در **یک فایل** است:

```json
// config/access.json
{ "mode": "open" }
```

| حالت | سهمیه‌های محصول | سقف لینک فعال هر پروژه | تاریخچه هر پروژه |
| --- | --- | --- | --- |
| `open` | برداشته شده | ۱۰۰٬۰۰۰ (سقف فنی) | ۱۰۰ نسخه / ۳۲ مگابایت |
| `locked` | جدول بالا | ۱۰ | ۲۰ نسخه / ۸ مگابایت |

تغییر حالت:

```bash
npm run access:status     # حالت فعال، منبع آن و سقف‌های فعلی
npm run access:locked     # بازگرداندن همهٔ سهمیه‌ها (نیازمند build دوباره)
npm run access:open       # برداشتن سهمیه‌های محصول
HERMIPLAN_ACCESS_MODE=locked npm run start   # بدون build؛ متغیر محیطی بر فایل مقدم است
```

فرمان‌ها **فقط** `config/access.json` را می‌نویسند (`updatedAt` و `note` را هم به‌روز می‌کنند)
و مقدار نامعتبر/ناشناخته همیشه به `locked` تفسیر می‌شود — یعنی خطای پیکربندی هرگز
بی‌صدا به «همه‌چیز آزاد» تبدیل نمی‌شود.

**آنچه در حالت `open` هم برداشته نمی‌شود** (عمدی): سهمیهٔ ورود و OTP، بررسی مالکیت روی
`/report/<id>`، قواعد انقضا/ابطال/یک‌بارمصرف لینک اشتراک، مرزهای بدنهٔ درخواست و خروجی
(۳ مگابایت)، و سقف‌های طرح پروژه در `src/lib/validation.ts` (۱۰۰۰ فعالیت، ۲۰۰ منبع/میله‌سنگ/ریسک).
حالت فعال روی `/api/health` هم گزارش می‌شود: `access.mode` / `access.source` / `access.shareLinkCap`.

## محدودیت نرخ (سهمیه هر endpoint)

همه سهمیه‌ها در PostgreSQL (`rate_limits`) و به‌صورت اتمیک نگهداری می‌شوند تا در محیط
serverless بین نمونه‌ها مشترک باشند. در نبود پایگاه داده، یک شمارنده حافظه‌ای **فقط** به‌عنوان
حالت تخریب‌شده (`degraded: true`) استفاده می‌شود و هرگز به «عبور بی‌قید» تبدیل نمی‌شود.

> **در حالت `open`** (بخش «حالت دسترسی») تمام سطرهای این جدول به‌جز سه سطر ورود
> (`RATE_LIMIT_AUTH`، `RATE_LIMIT_OTP_REQUEST`، `RATE_LIMIT_OTP_VERIFY`) برداشته می‌شوند.
> یعنی ساخت پروژه، تحلیل، خروجی و لینک اشتراک بی‌سهمیه‌اند؛ ورود و کد پیامکی همچنان
> محدود می‌مانند تا حساب‌ها و اعتبار پیامک قابل سوءاستفاده نباشد.

| Endpoint | کلید | پیش‌فرض | بازنویسی |
| --- | --- | --- | --- |
| `POST /api/analyze` | IP | ۶۰ / دقیقه | `RATE_LIMIT_ANALYZE` |
| `POST /api/export` | IP | ۳۰ / دقیقه | `RATE_LIMIT_EXPORT` |

## مدل دسترسی و امنیت

- **پیش‌فرض خصوصی**: گزارش هر پروژه فقط برای مالک (کوکی مهمان یا حساب کاربری) قابل مشاهده است.
- **لینک اشتراک با توکن ۲۵۶ بیتی**: `/report/<uuid>` فقط برای مالک باز است؛ مشاهده اشتراکی از مسیر
  `/s/<token>` انجام می‌شود. توکن با `crypto.randomBytes(32)` ساخته می‌شود و در پایگاه داده فقط
  **هش SHA-256** آن ذخیره می‌شود، بنابراین دامپ پایگاه داده به لینک قابل استفاده تبدیل نمی‌شود.
  هر لینک جداگانه قابل ابطال است (فوراً بی‌اثر می‌شود) و می‌تواند تاریخ انقضا داشته باشد؛
  ساخت/ابطال در `project_events` (`share-created`/`share-revoked`) ثبت می‌شود.
- **خاموش‌کردن اشتراک همه لینک‌ها را باطل می‌کند**: `PATCH` با `isPublic:false` در همان درخواست
  تمام توکن‌های فعال را باطل می‌کند تا لینک قدیمی از تصمیم مالک جان سالم نبرد.
- **شناسه UUID مجوز نیست**: درخواست غیرمالک همیشه ۴۰۴ می‌گیرد (نه ۴۰۳) تا وجود یا نبود پروژه
  افشا نشود. انتشار گزارش هم دسترسی به داده خام را باز نمی‌کند.
- **۴۰۴ توضیح‌دار، بدون افشا**: صفحه‌های `report/[id]/not-found.tsx` و `s/[token]/not-found.tsx` هر سه
  حالت (حذف‌شده، نشانی اشتباه، مالک نبودن) را با یک متن و یک کد وضعیت پاسخ می‌دهند، اما می‌گویند
  قدم بعدی چیست (باز کردن با همان مرورگر، ورود با حساب، درخواست لینک اشتراک تازه). پیش‌تر
  پیام عمومی «ممکن است حذف شده باشد» می‌گفت، که در حالت رایج (مرورگر دیگر) نادرست بود.
- **فایل پشتیبان پروژه**: پروژهٔ مهمان به کوکی همان مرورگر وابسته است؛ برای انتقال بین دستگاه‌ها از
  «پروژه‌های من ← فایل پشتیبان» یک JSON (`format: hermiplan-project`) بگیرید و در مرورگر دیگر
  «بازیابی از فایل» کنید. فایل، سند است نه مجوز: بازگردانی یک پروژهٔ **جدید** برای بازدیدکنندهٔ فعلی
  می‌سازد و محتوا هنگام خواندن با همان اسکیمای API اعتبارسنجی می‌شود (فایل خراب/بی‌پروژه/نسخهٔ آینده رد
  می‌شود). آزمون: `npm run test:project-file` (۳۱ بررسی).
- **ورود با نام کاربری و رمز عبور** (روش اصلی از این نسخه): رمز با **scrypt** و نمک تصادفیِ هر
  کاربر هش می‌شود (`scrypt$N$r$p$salt$hash`)؛ پارامترهای هزینه همراه خودِ هش ذخیره می‌شوند تا
  بعداً بتوان بدون باطل‌کردن حساب‌ها سخت‌ترشان کرد. رمز خام هرگز ذخیره، لاگ یا بازگردانده نمی‌شود.
  نام کاربری کوچک‌شده و **یکتا بدون حساسیت به بزرگی حروف** است (ایندکس یکتا روی `lower(username)`)،
  یعنی `Ali` و `ali` یک حساب‌اند و یکتایی را خودِ پایگاه داده تضمین می‌کند، نه یک `SELECT`.
  سیاست رمز: حداقل ۸ نویسه، شامل حرف و رقم، حداکثر ۲۰۰. `/api/auth` پاسخ نمی‌دهد کدام بخش
  («نام کاربری» یا «رمز») غلط بوده است و برای نام کاربری ناموجود هم یک تأییدیهٔ کامل scrypt اجرا
  می‌شود تا زمان پاسخ، وجود حساب را لو ندهد. سقف: ۱۲ درخواست/دقیقه به‌ازای هر IP و
  ۱۰ تلاش/۱۵ دقیقه به‌ازای هر نام کاربری (تست: `npm run test:password` و `test:api` §۶-ب).
- **راه ورود در رابط**: دکمهٔ «ورود / ثبت‌نام» در سربرگ صفحهٔ اصلی و در سربرگ سازنده (در همهٔ
  اندازه‌های صفحه، نه فقط دسکتاپ) و در منوی موبایل؛ نشانی `/builder?account=1` هم همان پنل را
  مستقیماً باز می‌کند (و پارامتر را از نوار نشانی پاک می‌کند تا رفرش دوباره بازش نکند).
- **OTP پیامکی (روش دوم/سازگاری)**: کد با CSPRNG ساخته می‌شود، فقط هش آن ذخیره می‌شود، ۵ دقیقه
  اعتبار، ۵ تلاش، مصرف اتمیک، فاصله ارسال مجدد و سهمیه جداگانه دارد. بدون سرویس پیامک، ورود با
  ۵۰۳ رد می‌شود مگر `HERMIPLAN_ALLOW_DEMO_OTP=1` در محیط غیر production. برای استفاده نیازی به
  پیامک نیست و رابط کاربری فقط نام کاربری/رمز نشان می‌دهد.
- **CSRF**: درخواست‌های تغییردهنده با بررسی `Origin`/`Sec-Fetch-Site` رد یا پذیرفته می‌شوند
  (دفاع اصلی، سمت سرور). کوکی نشست `HttpOnly` است و `SameSite=Lax` روی HTTP و
  `SameSite=None; Secure` روی HTTPS تنظیم می‌شود: مقدار `Lax` در یک قابِ cross-site توسط مرورگر
  فرستاده نمی‌شود و همان چیزی بود که گزارشِ صاحب پروژه را ۴۰۴ می‌کرد.
- **کلید قابلیت گزارش** (`/report/<id>?k=…`): مالک پروژه بدون نیاز به کوکی می‌تواند گزارش خودش را
  باز کند. کلید، HMAC-SHA256 شناسه پروژه است (کلید سرور: `HERMIPLAN_VIEW_SECRET` یا مشتق از
  `DATABASE_URL`)، فقط در پاسخ‌هایی که پیش‌تر مجاز بودند (ساخت/ذخیره/فهرست مالک) صادر می‌شود و
  فقط همان صفحه را باز می‌کند — نه تاریخچه، نه اشتراک، نه حذف. سرآیند `Referrer-Policy` مسیر را
  به مقصدهای بیرونی لو نمی‌دهد.
- پاک‌سازی شماره موبایل ارقام فارسی/عربی و همه قالب‌های رایج (`+98`، `0098`، `98`، `09`) را به
  یک شکل استاندارد تبدیل می‌کند و بقیه را رد می‌کند.
- **پروژه‌هایی که پیش از مهاجرت `0003` «عمومی» بودند** لینک UUID قدیمی‌شان کار نمی‌کند و هیچ
  توکنی به‌صورت خودکار برایشان ساخته نمی‌شود. `npm run db:share-audit` فهرست این پروژه‌ها را
  می‌دهد و مالک در پنل گزارش، پیام «لینک قدیمی غیرفعال است» به‌همراه دکمه ساخت لینک تازه می‌بیند.
- **تاریخچه نسخه‌ها**: هر ذخیره، یک نسخه‌ی تغییرناپذیر در `project_versions` می‌گذارد (فقط برای
  مالک). بازگردانی، پیش از اعمال، وضعیت فعلی را هم به‌عنوان نسخه ذخیره می‌کند؛ بنابراین خودِ
  بازگردانی هم قابل بازگشت است. شماره نسخه به‌عنوان توکن هم‌زمانی استفاده می‌شود: اگر دو تب با
  یک شماره ذخیره کنند، دومی **۴۰۹** می‌گیرد و نوشته اول بازنویسی نمی‌شود. تاریخچه با
  `PROJECT_HISTORY_LIMIT` (پیش‌فرض ۲۰، حداقل ۳) و `PROJECT_HISTORY_BYTES` (پیش‌فرض ۸ مگابایت)
  محدود می‌شود.
- **مقایسه نسخه‌ها**: پیش از بازگردانی می‌توانید هر نسخه را با وضعیت جاری (یا با نسخه‌ای دیگر)
  مقایسه کنید (`GET …/versions/:n/diff?against=current|<n>`). مقایسه روی سرور از داده‌ی ذخیره‌شده
  محاسبه می‌شود، فقط‌خواندنی است و هیچ فیلدی را نادیده نمی‌گیرد؛ فیلد ناشناخته هم با نام خام خودش
  گزارش می‌شود (`src/lib/report/version-diff.ts`).
- **CSP هیچ منبع بیرونی ندارد**: فونت وزیرمتن خودمیزبان است (`public/fonts/`) و `style-src`/`font-src`
  دیگر `cdn.jsdelivr.net` را مجاز نمی‌کنند.

## صداقت داده و محدودیت‌های شناخته‌شده

- کاتالوگ نرخ داخلی **سند رسمی ندارد** و در همه‌جا «مرجع» نامیده می‌شود، نه «مصوب» یا «رسمی».
  هر ردیف نوع، واحد، تاریخ مرجع و وضعیت اعتبار (`unverified` / `verified` / `reference-estimate`)
  دارد. عدد فهرست‌بها یا شاخص اقتصادی در این مخزن تولید یا حدس زده **نمی‌شود**.
- «سناریوی افزایش هزینه» یک تورم مرکب ماهانه فرضی است، **نه** تعدیل قراردادی و **نه** شاخص رسمی.
- قیمت «لحظه‌ای» فقط وقتی نمایش داده می‌شود که `HERMIPLAN_MARKET_FEED` تنظیم شده و پاسخ فید
  معتبر باشد؛ در غیر این صورت عبارت «کاتالوگ مرجع» با تاریخ مرجع دیده می‌شود.
- تسطیح خودکار منابع پیاده‌سازی نشده است؛ بیش‌تخصیص شناسایی و گزارش می‌شود و تصمیم با برنامه‌ریز است.
- ارجاع به استانداردها (PMBOK/ISO/AACE/فهرست‌بها) به‌معنای گواهی انطباق نیست.
- CSP با nonce در `src/middleware.ts` اعمال می‌شود: `script-src` بدون `'unsafe-inline'` و بدون
  `'unsafe-eval'` در production. `style-src` ناچار `'unsafe-inline'` دارد (۲۰+ ویژگی `style` در
  React که nonce نمی‌پذیرند) — این محدودیت مستند است، نه فراموش‌شده.
- آزمون مرورگری (اسکرین‌شات موبایل/دسکتاپ، PDF چاپی) در این محیط اجرا نشده است: باینری‌های
  Chromium به کتابخانه‌های سیستمی `libnspr4`/`libnss3` نیاز دارند که نصبشان root می‌خواهد.
  به‌جای ادعا، رندر پیکسلی نمودار و قواعد چاپ با `npm run test:layout` و ساختار سند با
  `npm run test:a11y` سنجیده می‌شود.
- **PDF سمت سرور تولید نمی‌شود**: قالب `pdf` یک سند HTML آماده چاپ (`@page A4`، فونت جاسازی‌شده،
  بدون منبع بیرونی) برمی‌گرداند و PDF نهایی با «چاپ → Save as PDF» مرورگر ساخته می‌شود. نام فایل و
  `Content-Type` هم همین را صادقانه اعلام می‌کنند (`.html` / `text/html`) — ادعای PDF نمی‌شود.
- **خروجی‌ها تکرارپذیرند**: مهر زمانی آرشیوهای XLSX/ZIP از تاریخ وضعیت پروژه گرفته می‌شود، پس
  صدور دوباره‌ی همان پروژه بایت‌به‌بایت یکسان است (قابل هش و مقایسه).

## نکات کیفی

- محاسبات پروژه توسط موتور اختصاصی و **deterministic** انجام می‌شود؛ هوش مصنوعی منبع محاسبات نیست.
- تمام تقسیم‌ها محافظت‌شده‌اند: شاخص تعریف‌نشده `null` است و در گزارش `—` نمایش داده می‌شود، هرگز
  `NaN`، `Infinity` یا صفرِ گمراه‌کننده.
- هر تغییر در `analysis.ts`/`schedule.ts`/`market/engine.ts` باید با اجرای کامل `npm test` تأیید شود.
